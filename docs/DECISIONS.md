# 決策紀錄（Decisions）

本文件記錄 FSRS 記憶卡應用的產品與技術決策。標記 **【已確認】** 的是與使用者討論後確定的項目，其餘為預設決策，可隨時調整。

---

## 1. 產品定位

- 個人用、離線優先（local-first）的 FSRS 記憶卡 PWA。
- 介面語言：繁體中文。
- 所有資料先存在瀏覽器的 IndexedDB，雲端（Google Drive）只用來同步與備份。

## 2. UI 風格

使用者提供了 UI 範例圖作為參考。**配色沿用範例圖的色調**（使用者指定），元件形狀與版面則使用自己的設計：

- **配色**：淺灰米色底（`#eeedea`）＋白色卡片；預設主色為柔和藍 `#5f93c4`；牌組使用粉彩色（藍、黃、粉、橘、綠、紫、灰）。深色模式為深灰底（`#2b2b2b`），粉彩色會自動調暗。
- **主色可在設定中更改**：8 個預設色票＋自訂色，主色寫成 CSS 變數（`--primary`），淺色與深色變體自動計算。
- **形狀**：中等圓角（卡片 16px、按鈕與輸入框 12px、小標籤 6px），卡片有細邊框；icon 按鈕為圓角方形。
- **字體**：拉丁文字用 **Inter**，中日韓文字用系統字體（Noto Sans TC / PingFang / 微軟正黑）。
- **分頁切換**：分段控制器（segmented control）。
- **牌組清單**：分組清單，每一列有粉彩色的圖示方塊、名稱與張數、可複習／新卡數量徽章、稍後到期倒數、箭頭；子項目以縮排顯示。清單頂端有圖例說明徽章顏色的意義。
- **導覽**：底部全寬分頁列（首頁／統計／設定）；新增牌組的按鈕放在「牌組」標題旁，不使用浮動按鈕。
- **下拉選單**：隱藏瀏覽器預設箭頭，改用 lucide 的 ChevronDown 圖示（`SelectBox` 元件）。
- **深色模式**：首頁右上角的太陽／月亮按鈕可以快速切換；設定中也可選「跟隨系統／淺色／深色」。
- **不設計 App 名稱與 logo**：介面上不顯示品牌名稱或圖示。PWA 安裝必須提供名稱與圖示，因此 manifest 只使用描述性的「FSRS 記憶卡」與純色圓角方塊圖示。
- 手機優先的版面（最大寬度約 672px，桌機置中）。

## 3. 資料結構

### 3.1 牌組

- 只有「牌組」一種（早期版本的「資料夾」已合併進牌組）。
- **牌組**：可以放子牌組 *或* 卡片，兩者互斥。空牌組兩者都能新增；已有卡片的牌組不能新增子牌組；已有子牌組的牌組不能新增卡片。
- **舊資料**：啟動時把舊的資料夾轉成牌組（更新 `updatedAt`，會同步到其他裝置）；同步收到舊版裝置傳來的資料夾也一律當牌組處理。
- 每個牌組都有「複習／新學習／練習」入口，範圍是它底下所有子牌組的卡片。有兩個以上牌組時可以勾選只學其中幾個（選擇記在這台裝置，依範圍分開記）。
- **預設卡片模板**：牌組設定可以選「新增卡片」的預設模板：先選正反卡（未設定時的預設）或單字卡；選單字卡時再選語言（沿用上次／英文／日文／韓文）。牌組頁只有一個「新增卡片」按鈕，會依預設模板開啟編輯畫面，在編輯畫面中仍可切換模板與語言。

### 3.2 卡片

兩種類型：

| 類型 | 欄位 | 判斷「已完成」的條件 |
|---|---|---|
| 正反卡 `basic` | 正面（Markdown）、反面（Markdown） | 正、反面都有內容 |
| 單字卡 `vocab` | 語言（en/ja/ko）、單字、讀音（選填，日文假名／音標）、意思（純文字，不使用文字編輯器）、詞性（多選）、例句[]（例句＋翻譯）、備註（選填） | 單字與意思都有內容 |

- **未完成卡片**：可以只先填正面（或單字），會標示「未完成」，不會進入複習、新學習或練習。
- 每張卡片都有 **星號** 和 **暫停** 標記。暫停的卡片不會進入複習／新學習。
- **【已確認】單字卡例句可以有多筆。** 正面點擊「查看例句」時會隨機顯示一句（不含翻譯）；翻到反面時，會顯示那一句的翻譯，並可點擊「查看更多」展開所有例句。
- **【已確認】正式複習預設只考「單字 → 意思」**，一張卡一份 FSRS 排程。**練習模式可以選擇反向（意思 → 單字）。**
- **牌組可開啟「反向學習」**（牌組設定，預設關，可沿用上層）：只對單字卡有效，每張卡多一份獨立排程 `rsched`（意思 → 單字），複習紀錄用 `side: 'r'` 區分。
  - 正向進入複習狀態後，反向才開始以新卡出現；反向的新卡與複習都**不計入**每日上限（數量上由正向的新學習節奏自然限制）。
  - 關閉後反向進度保留（只是不再排程），重新開啟可接續；「重設」卡片會一併清除反向進度。
  - 同一個字的正反兩面不會連續出現（學習中的卡片）；撤銷與重新評分都以「同一面的最後一次」為準。
  - 統計頁與卡片列表仍只看正向排程。

### 3.3 詞性預設（設定中可改名、排序、隱藏、新增自訂、可還原）

- 設定中用拖曳把手調整順序（滑鼠與觸控都可以）；拖曳中的那一列以輸入框的主色框標示。
- **預設詞性不能刪除，只能隱藏**【已確認】：隱藏後不出現在編輯卡片的選項中（若該卡片已標記則仍顯示，方便取消），已標記的卡片照常顯示。自訂詞性可以刪除，刪除前一律跳出確認視窗（有卡片使用時會註明張數）【已確認】；刪除後卡片上直接不顯示，不會出現代號。
- 卡片存的是詞性 ID。預設詞性的 ID 寫死在程式中，發布後不可更改：改名只改 label，新增預設詞性要用新 ID。
- **使用者資料保護**：使用者的詞性清單整份保存，不會被新版預設值覆蓋。載入或同步設定時，清單中缺少的預設詞性（也就是新版新增的）會自動加到最後面，不影響使用者的改名、排序與隱藏。「還原預設」只恢復預設詞性的名稱、順序與顯示，自訂詞性保留；「重置所有設定」也一樣。

- 英文：名詞 n.、動詞 v.、形容詞 adj.、副詞 adv.、代名詞 pron.、介系詞 prep.、連接詞 conj.、感嘆詞 int.、片語 phr.、片語動詞 phr. v.
- 日文：名詞、動詞（五段）、動詞（一段）、動詞（する）、動詞（不規則）、い形容詞、な形容詞、副詞、助詞、接續詞、感嘆詞、連體詞、慣用語
- 韓文：名詞、動詞、形容詞、副詞、代名詞、助詞、冠形詞、感嘆詞、數詞、慣用語

### 3.4 儲存

- 使用 **Dexie（IndexedDB）**。資料表：`nodes`（牌組樹）、`cards`、`logs`（複習紀錄）、`meta`（設定等）。
- 每筆資料都有 `id`（UUID）、`updatedAt`，刪除時只標記 `deleted`（墓碑），方便多裝置同步。

## 4. Markdown 編輯器與防劇透

- **【已確認】Markdown 原始碼＋工具列＋預覽。**
- 使用 `markdown-it` 渲染，並用 `DOMPurify` 消毒 HTML。
- 工具列：粗體、斜體、刪除線、標題、清單、引用、行內程式碼、連結、**防劇透**。
- 防劇透語法跟 Discord 相同：`||被遮住的文字||`，顯示時是一塊色塊，點擊才會顯示內容。

## 5. FSRS 與排程

- 使用 `ts-fsrs`。設定項：
  - **目標熟悉度（request_retention）**：預設 90%，範圍 70–99%。調整時即時顯示提示：「相較 90%，複習間隔約為 x 倍，每日複習量約為 y 倍」。依據 FSRS 的遺忘曲線公式計算，數字越高記得越牢，但複習次數越多。
  - 最大間隔（預設 36500 天）、間隔隨機化（fuzz，預設開）、學習步驟（預設 `1m 10m`）、重新學習步驟（預設 `10m`）。
  - 學習步驟與重新學習步驟收在「進階」摺疊區（格式錯誤時自動展開），並說明留空表示不做當天的短期複習。
- **【已確認】每日上限**：全域預設「新卡 20／複習 200」，每個牌組可覆寫。上層牌組範圍的學習會依各牌組自己的上限累計；上層牌組的上限只管它自己的卡片。
- 新卡順序：建立順序（預設）或隨機。
- 複習卡（Review 狀態）只要在「今天這個學習日結束前」到期就會出現；學習中的卡（Learning/Relearning）依實際到期時間出現。若佇列只剩尚未到期的學習中卡片，會顯示倒數，並可選擇「提前複習」。
- **倒數顯示**【已確認】：今天還有學習中的卡片、但時間還沒到時，以「分:秒」倒數顯示：
  - 首頁與牌組頁的「複習」按鈕：沒有其他可複習的卡片時顯示倒數；有的話顯示「N 張」，並在下方附上「+M 張 · 倒數」。
  - 牌組清單每一列：顯示計時器圖示和倒數。
  - 複習中的等待畫面：以大字顯示倒數，時間到會自動出現下一張。
  - 倒數歸零時，可複習數量會立即更新（排定在最近的到期時間刷新），不需要等定期更新。

## 6. 學習日與換日時間

- 預設換日時間為 **04:00**。在 10/09 01:00 複習，會算在 10/08 的學習日。
- 每筆複習紀錄都會存下它所屬的 `studyDay`（YYYY-MM-DD）。
- **修改換日時間時，只重新計算「前一個學習日」與「今天」的紀錄**，更早的紀錄不會變動。
- 不考慮時區問題，一律使用裝置的當地時間。

## 7. 正式複習的「恢復重選」【已確認】

- **今天（目前學習日）複習過的卡片都可以重新評分。**
- 如果同一張卡今天被複習多次（例如按了「困難」，10 分鐘後又排進來），**只能重評最後一次的紀錄**，更早的那次不能改。
- 實作：每筆紀錄都會存「評分前的卡片狀態快照」。重評時，先把卡片還原到快照，標記舊紀錄為刪除，再用新的評分重新排程。
- 入口：
  1. 複習中按「上一步」（撤銷剛剛的評分，卡片回到佇列最前面）。
  2. 卡片詳情頁中，若最後一次紀錄是今天，會出現「重新評分」。選好新評分後會先跳出確認視窗，列出紀錄時間、原評分→新評分與新的下次間隔，按「修改」才會套用【已確認】。

## 8. 練習模式

- 可從牌組／卡片列表進入，並可篩選與勾選要練習的卡片。
- 選項：題目順序（隨機／依序）、單字卡方向（單字→意思／意思→單字／混合）、是否包含暫停的卡片。
- 練習時只有「記得／忘記」兩個按鈕，忘記的卡片會在本輪稍後再出現一次。**完全不寫入 FSRS 排程與紀錄。**

## 9. 卡片篩選、排序與批次操作

- 篩選：星號、暫停、已學習／未學習（是否有複習紀錄）、未完成、卡片狀態（新／學習中／複習／重新學習）、熟悉度區間、單字語言、關鍵字搜尋。
- **熟悉度** = FSRS 當下的「記得機率」（retrievability，0–100%），新卡沒有熟悉度。
- 卡片詳情的數值區中，有說明的項目在標籤旁有問號圖示，點標籤會在該列下方展開說明（一次一則），涵蓋狀態、熟悉度、穩定度、難度、下次複習、複習／遺忘次數（例如剛複習完熟悉度一定是 100%）。
- 排序：建立時間、更新時間、到期日、熟悉度、正面文字／單字字母順序（可升冪或降冪）。
- 批次：加／取消星號、暫停／恢復、移動到其他牌組、刪除、練習所選卡片。

## 10. TTS 發音

| 語言 | 預設引擎與聲音 | 其他可選 |
|---|---|---|
| 英文 | **Kokoro-82M `af_heart`**＋misaki 發音字典【已確認】 | Kokoro 其他 6 個美式聲音、系統語音（英文 Piper 已移除【已確認】） |
| 日文 | **Kokoro-82M `jf_alpha`**【已確認】 | Kokoro 其他 3 個日文聲音、系統語音 |
| 韓文 | Piper 官方 `ko_KR-kss-medium`＋espeak-ng【已確認：方案 B】 | 系統語音 |

### Kokoro（日文、英文）

- 模型：`onnx-community/Kokoro-82M-v1.0-ONNX`（Apache-2.0），日文、英文共用同一個模型。
  - 日文聲音：`jf_alpha`、`jf_gongitsune`、`jf_nezumi`、`jm_kumo`。Kokoro v1.0 的日文聲音只有這幾個，`jf_tebukuro` 不使用【已確認】。
  - 英文聲音（美式）：從 Kokoro v1.0 的 20 個美式聲音中精選【已確認】：女聲 `af_heart`、`af_aoede`、`af_bella`、`af_kore`，男聲 `am_fenrir`、`am_michael`、`am_puck`（官方評分較高的幾個）。英式聲音需要另一套英式發音字典，暫不提供。Kokoro 沒有韓文。
  - 合成前若音素結尾沒有句末標點，會補上句點：Kokoro 沒有句末標點時會把最後一個音截短（例如 arrange 少了 ge 的音）。
  - 聲音的 style 向量依官方 KPipeline 取第「音素數 − 1」列。這兩項改動後，發音快取的鍵加上版本號（`KOKORO_REV`），舊的 Kokoro 快取不再使用。
- 英文前處理（`src/lib/tts/enG2p.ts`）：
  - 原因：Piper 用 espeak-ng 把單字轉成音標，會固定念錯一些字，例如 arrange、around 被轉成 `ɚɹ…`，聽起來像 rrange【已確認改用 Kokoro】。
  - 移植 misaki 的英文前處理（Apache-2.0），也就是 Kokoro 訓練時用的格式：先查 misaki 的 gold／silver 發音字典（約 18 萬字，`us_gold.json`、`us_silver.json` 共約 1.5MB gzip，隨專案部署、用到才下載），再套用 -s／-ed／-ing 字尾規則；字典沒有的字（含數字、金額）才交給 espeak-ng，並轉換成 Kokoro 的音素，`ɚɹ` 也會修正成單一個 r。
  - 沒有 spaCy 詞性標註，所以同形異音字（record、read、live 等）一律用字典的預設讀法；a、the、to 等虛詞依前後文調整。
- 日文前處理（`src/lib/tts/jaG2p.ts`）：現成的 kokoro-js 只支援英文，所以自行實作：
  - 移植 misaki 的 cutlet 日文前處理（Apache-2.0，源自 polm/cutlet，MIT），這是 Kokoro 訓練時使用的音素格式；數字讀法移植自 misaki 的 num2kana。
  - 原本使用的 MeCab＋UniDic 改用 **kuromoji.js（IPADIC）** 斷詞與取得讀音，辭典約 17MB，從 jsDelivr 下載後存在 Cache Storage。
  - 斷詞分組用的 misaki 詞表 `ja_words.txt`（約 1.9MB，gzip 後約 0.5MB）隨專案部署。
- 在 **Web Worker** 中執行（`kokoro.worker.ts`），合成時畫面不會卡住。
- 兩種執行方式（設定中選擇）：

  | 模式 | 模型 | 下載量 | 速度（合成 1 秒語音） |
  |---|---|---|---|
  | 標準（預設） | 8-bit 量化版，CPU（WASM） | 約 92MB | 約 2–3 秒 |
  | 高速 | fp32，WebGPU | 約 326MB | 約 0.3–0.4 秒（第一次約 3.5 秒） |

  - GitHub Pages 無法設定跨來源隔離標頭，onnxruntime 只能用單執行緒，所以 CPU 模式較慢。
  - 量化版在 WebGPU 上反而更慢（大部分運算退回 CPU），fp16 版在 WebGPU 上會輸出 NaN，因此高速模式只能用 fp32。
  - 不支援 WebGPU 的裝置只顯示標準模式。

### 其他引擎

- **piper-plus（已移除）**：つくよみちゃん、CSS10 兩個聲音以日文語料訓練，英文有口音、日文也不如 Kokoro，因此整個移除，不再提供自訂 ONNX 模型網址【已確認】。
- **Piper 官方聲音＋espeak-ng（韓文）**：自行實作的執行器（`espeakPiper.ts`），espeak-ng WASM（約 18MB，`espeak.ts`，Kokoro 英文的備援也共用）隨專案部署，聲音模型每個約 63MB。官方日文聲音使用 OpenJTalk 音素，這個執行器無法使用。
- **系統語音（Web Speech API）**：任何神經網路聲音載入失敗或不支援時自動改用。

### 共通

- **發音快取**：合成好的音訊永久存在 Cache Storage（`tts-audio`，最多約 4000 筆），同一個字、同樣的聲音與速度只合成一次。
- **試聽範例**：每個神經網路聲音朗讀設定頁範例句的錄音預先產生好，放在 `public/tts-samples/`（12 個 WAV，共約 1.2MB）。「試聽」直接播放這些檔案並套用速度設定（保留音高），不需要下載模型；找不到檔案或離線時才即時合成【已確認】。修改範例句或新增聲音時要重新產生。
- **照讀音發音**【已確認】：單字卡填了讀音時，發音（含自動朗讀、背景預先合成）優先照讀音，用來指定多音字、同形異音字的念法；讀音看不懂時改念單字，例句不受影響。
  - 英文（Kokoro）：IPA（`/əˈreɪndʒ/`）或 KK 音標（`[əˋrendʒ]`）轉成 Kokoro 音素；有多個讀音時取第一個 `/…/` 或 `[…]`，括號外的註記（如「(n.)」）略過。單獨的 `e` 在 KK（方括號或有 ˋ ˏ 重音）代表 eɪ，在字典 IPA 代表 ɛ。系統語音仍念單字。
  - 日文：只有假名的讀音才使用（Kokoro 與系統語音都適用）；寫了多個讀音（以 ／、、 等分隔）時改念單字。
  - 韓文：只有韓文字的讀音才使用（可帶 `[ ]`），例如 읽다 填 `[익따]`。
- **背景預先合成**：單字卡出現時先合成單字；點「查看例句」時先合成例句；複習中也會先準備下一張卡片的單字。
- **音量**：模型輸出統一正規化到峰值 0.9（最多放大 4 倍）。
- 授權：KSS 語料為 CC BY-NC-SA 4.0；espeak-ng 為 GPL-3.0。本專案僅供個人使用、不會有任何商業用途（見 README），因此可以接受。
- 設定（依語言分開）：引擎、聲音、速度（0.5–2.0×）、Kokoro 執行方式、自動朗讀開關（預設關閉）。舊版設定會自動轉移：存的聲音不屬於該語言的可選聲音時換成預設聲音（例如英文原本選 Piper 聲音的，會換成 Kokoro Heart）。
- TTS 設定屬於「裝置設定」，**不會同步**。

## 11. 字典

- 設定中可以管理字典清單：名稱、網址樣板（用 `{word}` 代表單字）、適用語言。
- 預設：
  - Mazii（日文）：`https://mazii.net/zh-TW/search/word/jatw/{word}`
  - 劍橋詞典（英文→繁中）：`https://dictionary.cambridge.org/zht/詞典/英語-漢語-繁體/{word}`
  - Naver 韓中詞典（韓文，額外加入的預設，可刪除）：`https://korean.dict.naver.com/kozhdict/#/search?query={word}`
- 在複習、練習、預覽卡片時，可以點擊字典按鈕查詢。**因為這些網站都禁止被內嵌（iframe），所以一律開新分頁顯示查詢結果。**

## 12. OCR 新增單字【已確認：Tesseract.js】

- 使用 Tesseract.js 在本機辨識，首次使用某語言時會下載語言檔（英文約 4MB，日文／韓文約 10MB 以上）。
- 流程：選擇或拍攝圖片 → 選擇語言 → 辨識 → 顯示辨識結果，可以點選單字或直接編輯文字 → 勾選要加入的單字 → 批次建立成「未完成」的單字卡（之後再補上意思）。

## 13. Google Drive 同步與備份【已確認：多裝置同步＋備份；自動、手動各保留 3 份】

- 使用 Google Identity Services（GIS）取得 OAuth token，scope 為 `drive.appdata`（只能存取本 App 的隱藏資料夾，看不到使用者的其他檔案）。
- **登入視窗只在點擊當下開啟**：瀏覽器會擋下不是由點擊直接開啟的彈出視窗，因此 Google 登入元件會預先載入，點擊後不經過任何等待就開啟視窗；頁面載入或操作進行到一半時都不會自動跳出登入視窗，授權中途失效時改為提示「請再按一次」。登入時若沒有勾選雲端硬碟權限，會提示重新授權。
- **需要使用者在 Google Cloud Console 建立 OAuth Client ID**，並把 GitHub Pages 網址加入「已授權的 JavaScript 來源」。Client ID 可以在設定中填寫，也可以在建置時用 `VITE_GOOGLE_CLIENT_ID` 環境變數指定。
- **同步**：
  - 雲端檔案為 `sync.json.gz`（gzip 壓縮的完整快照）。
  - 合併規則：每筆資料以 `updatedAt` 較新的為準（Last-Write-Wins），刪除使用墓碑標記；複習紀錄只增不改（重評時舊紀錄標記刪除）。
  - 衝突提示：同一筆資料在上次同步後兩邊都改過、內容又不同時，仍以較新的為準，但會跳出提示，並在同步設定顯示衝突數量（卡片、牌組、複習紀錄、設定），按「知道了」才消失。從未同步過的裝置不判斷衝突。
  - 上傳前會再確認雲端檔案沒有在合併期間被其他裝置更新；有更新就重新合併（最多 3 次），避免覆蓋其他裝置剛上傳的資料。
  - 觸發時機：開啟 App、完成一輪複習、離開頁面（切到背景）、手動按同步。
  - 已知限制：兩台裝置在離線時都複習了同一張卡，卡片的排程會以較晚的那次為準，但兩筆紀錄都會保留。
- **備份**：
  - 自動備份：每天第一次同步時建立，**保留最新 3 份**。
  - 手動備份：在設定中按下建立，**另外保留最新 3 份**。
  - 可以從任一份備份還原（還原前會先確認）。
- **首頁同步狀態**：未連線／同步中／已同步（顯示時間）／有未同步的變更／需要重新登入／錯誤。
- 限制：純前端無法在背景長期更新 token（約 1 小時過期），過期後會顯示「需要重新連線」，點一下即可。
- 另外提供**本機 JSON 匯出／匯入**，作為不依賴 Google 的備份方式。

## 14. 設定

分組以**可折疊的區塊**呈現（預設全部收合，標題下方有簡短說明；從其他頁面以 `#區塊` 連結進來時會自動展開該區塊），不使用頂部的跳轉標籤。可還原的組別在展開後的底部有「還原預設」：

1. 外觀：主色、深色模式
2. 學習：換日時間、每日新卡／複習上限、新卡順序
3. FSRS：目標熟悉度（含提示）、最大間隔、fuzz、學習步驟、重新學習步驟
4. 詞性：英／日／韓詞性清單（拖曳排序）
5. 發音（TTS）：各語言的引擎、聲音、速度；自動朗讀
6. 字典：字典清單
7. 同步與備份：Google 連線、Client ID、立即同步、自動同步開關、備份清單與還原
8. 資料：匯出／匯入 JSON、清除所有資料

- 最下方有「重置所有設定」（需確認）：外觀、學習、FSRS、詞性、發音、字典全部回到預設；卡片、複習紀錄與 Google Drive 連線不受影響【已確認】。
- 滑桿（目標熟悉度、發音速度）使用固定大小的拖曳點，刻度與標籤依數值精確對齊；點標籤可直接跳到該值。
- 「同步設定」（外觀、學習、FSRS、詞性、字典）會跟著資料同步到其他裝置；「裝置設定」（TTS、Google 連線狀態）只存在本機。
